#+TITLE: LeanPoo

LeanPoo is a Lean 4 library for prototype-oriented object composition and
incremental proof reuse. It implements the functional prototype construction
described in [[https://github.com/metareflection/poof][POOF]] with Lean's types, functions, and thunks. Its C4
linearization follows [[https://github.com/fare/c4-mixins][C4-Mixins]]. [[https://github.com/tao3k/gerbil-poo][Gerbil-POO]] informs the object-level design.

The reviewed Lean-native constructive path is implemented and checked, including
Order/BST/AVL, source/Lean differential checks, C3 object composition, runtime
descriptors and mutable hash slots. [[file:docs/contracts/recursive-objects.org][Safe recursive objects]] have sound/complete
operational evaluation and divergence theorems.
[[file:docs/contracts/shared-thunks.org][Checked shared thunks]] connect native execution of explicit recursive interactions
to exact-program evaluation receipts and the existing C3 field/method observers.
The existing ~sharedFix~ and its primitive model execute one shared constructor
program; checked operation logs refine the shared-cell protocol.
[[file:docs/contracts/c3-graph.org][C3 cache coherence]] proves complete cached/reference results for every finite
graph and root list, including exact cyclic and validation failures.
The [[file:docs/audits/poof/README.org][whole-paper audit]] records the precise typed scope. Whole-paper operational
correspondence and unrestricted dynamic automation are not established.

The library is domain-neutral: applications supply their own typed keys,
values, obligations, and dependency graph. It does not define a policy
language or a domain-specific proof system.

* What it provides

| Layer | Public capability |
|-------+-------------------|
| ~LeanPoo.Prototype~ | Open-recursive prototypes, safe recursive observations, ordered composition, delayed instances, first-class descriptors, mutable slots and classes. |
| ~LeanPoo.C4~ and ~LeanPoo.Object~ | Typed object definitions, explicit C3/C4 precedence, inheritance, override, mix, clone, lazy reads, persistent revisions, and checked incremental value and thunk reuse for finite dependencies. |
| ~LeanPoo.Proof~ | Proof objects, patches, obligations, dependency-based invalidation, certificate reuse, and closure. |
| ~LeanPoo.Functional~ | Context-indexed factories, positive and negative requirements, certified consumers, immutable registry transactions, verified graph migration, inferred pure dependencies, computed cache revisions and witness transformations. |
| ~LeanPoo.Deriving~ | Automatic typed class/structure dictionary conversion with kernel inverse proofs and adapters for prototypes, descriptors and consumer caches. |
| ~LeanPoo.Object.Debug~ | Public bounded read tracing and recursive-read diagnostics for object development. |

Lean's type system expresses slot families and composition boundaries. The
general open-recursive fixed point is executable and may diverge; the debug
API bounds reads made through that API, while the example runner adds process
time and memory limits. The [[file:docs/replication.org][implementation assessment]] records the precise scope and
runtime boundary.

* Get started

Install the Lean toolchain named in [[file:lean-toolchain][lean-toolchain]]. Build the library with
~lake build~. The full project check uses ~just~, ~zsh~, Emacs for Org parsing,
Python 3, and a ~timeout~ command. The complete local gate checks independent
Lean files with automatically bounded workers after the public library build;
[[file:docs/check-performance.org][check performance]] records the host-dependent worker limits:

#+begin_src sh
lake build
just check
#+end_src

The smaller Justfile targets include ~check-c4~, ~check-object~,
~check-proof~, ~check-debug~, and ~check-docs~. The documentation check uses
Pandoc's Org reader and the existing Python audit; it does not require Emacs.
It parses the four directory/root indexes and every Org file under ~docs~ with
separate file scopes, without executing source blocks or producing output files. Use ~just check-incremental true~
or ~just check-debug true~ to print semantic diagnostics only when needed.

* Research extension: generalized prototypes

[[file:docs/contracts/generalized-prototypes.org][The generalized protocol]] advances the paper's future work by separating raw
construction, cooked self and fragment compilation. It reuses C3, nested lenses,
method combinations and exact representation bridges, with finite-observation
and witnessed-closure laws. [[file:Examples/GeneralizedService.lean][GeneralizedService]] and [[file:Examples/GeneralizedCheckout.lean][GeneralizedCheckout]]
exercise those compositions. This is an initial typed protocol, not completion
of the paper's full MOP research proposal.

* Certified witness transformations

=LeanPoo.Functional.Transformation= exports input-indexed =Problem= and
=CertifiedTransformation=, identity, ordered composition, soundness, and
forward/extraction associativity. =LeanPoo.Proof.Transformation= checks a
concrete two-step transport. Runtime source authority, codec refinement,
resource authorization, and publication remain consumer obligations.

=LeanPoo.Functional.TransformationProfiles= adds separate certified laws for
bidirectional decision reductions, successful partial transport, and optimality
transport. An unavailable partial result is =none=; a witness proof alone cannot
construct a decision equivalence or optimality reduction.

=LeanPoo.Functional.TransformationResources= composes affine output-size and
cost bounds at the actual intermediate input. =CertifiedResourceTransformation=
requires bounds on the declared implementation's measured size and cost.
=CertifiedEffectTransformation= composes the actual forward and reverse effect
traces, retaining authorization at each state transition. These are generic
proof interfaces: native consumers supply implementation refinement, measurements,
authority and publication. The modules do not infer CPU complexity or permission
from an unverified declaration.
