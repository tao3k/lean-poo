* Research proposals and project extensions

The cache section (1525–1559) discusses explicit caches and language-wide purity
or effect tracking. Current dependency schedules, incremental revisions and
proof reuse depend on explicit finite contracts. They do not inspect arbitrary
Lean bodies or implement a language-wide invalidation policy.

That distinction is a research boundary, not a claim that the paper supplied
an algorithm we failed to copy. Likewise, OpenAI factory/consumer audits and C4
contract APIs are local extensions. Their existence and large test corpus do
not establish full POOF implementation coverage.

* Executable representation and meta controls

The =Indexed= key-preparation refinement uses the already admitted C4 layer
indexes. =prepareKey_sound= preserves the original default pass, inherited
method chain and arbitrary final self. Concrete other-key method/default
edits preserve the selected payload projection. =prepareKey_frame= shares
only the unbound recipe; different receivers can still produce different
values. Five controls distinguish final self, inherited defaults, false and
absence. The projection length counts C4 layers rather than all field names.
This refines the representation unit at paper lines 980–1038. Native payload
capture, hooks, raw exposure, index construction and latency remain separate
obligations; no Scheme implementation or speedup follows from these laws.

The =SlotPreparation.PayloadCapture= extension specifies the preceding
closed source phase. A handle names an actual required validation/capture
field, not a whole receiver revision. Successful capture reads the complete
scheduled support and preserves its order; append composition preserves the
first error. Equality of the actual field reads transports that captured
result across a source change outside its support. Constructive controls
reject skipping an invalid unrelated contribution, reordering two failures,
and moving a constant payload capture across an author callback.

This is a project capture contract, not an additional implemented paper unit
or a complete Scheme source issuer. Its read schedule must be derived from
the actual preparation phases: stock validation can inspect a shadowed tag
without capturing a discarded payload. The model does not authorize reading
all discarded fields, freezing every reachable value, sharing receiver
results, skipping hooks, or treating a sealed container as immutable support.
The existing =Indexed= laws still own demanded method resolution. Native
write coverage, raw method-table exposure and phase correspondence remain
integration obligations before a point-preparation runtime can use it.

The =CapturedBinding= refinement supplies a narrower constructive step.
After original tag admission and payload capture, =newest_callable_exact=
classifies each native most-specific-first chain from its captured head,
without constructing receiver method closures. =all_keys_refusal_exact=
preserves the complete ordered callable-check result and first failing key.
Unused malformed thunk payloads remain hidden by the same retained wrappers;
no body is evaluated by this classification. A hook-repair counterexample
requires the original hookful path: an author hook may turn a non-callable
next result into a valid procedure. Native capture issuance, method-cell
storage/reflection, supported concurrency and actual performance remain open.

The =SlotPreparation.EffectfulAdmission= refinement makes installation
effects explicit. =without_hooks_exact= preserves ordered results, errors
and final state when each selected write preserves protocol absence.
=initial_absence_is_insufficient= refutes hoisting on initial absence alone:
a write between two entries can install a protocol seen by the second entry.
Gerbil's selected HashTable write route must supply this frame before the
Scheme loop can use the law. This is an implementation obligation under
the paper's representation and mutation discussion, not additional coverage
of a paper algorithm or a measured latency improvement.

* Dynamic and mutable completion

[[file:../../contracts/recursive-objects.org][The recursive object guide]] describes dynamic values, first-class runtime
descriptor identities, recursive named contracts and reflective contract data.
Successful membership and checked function calls have kernel soundness.
The mutable hash protocol performs slot insertions on one shared identity,
captures inherited syntax and resolves final self on later reads. Pure, mutable
and consuming-state observations are compared, including partial errors and
snapshot isolation. [[file:../../../LeanPoo/Prototype/MutableRecordSemantics.lean][MutableRecordSemantics]] proves complete state/status
projection and all-key/all-depth observations. The concrete IO adapters execute
the same interpreter; failures retain partial writes in all three carriers.
