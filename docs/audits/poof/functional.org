* Review identity

This map uses the same pinned ~poof.scrbl~ and source intervals as the
[[file:requirements-v1.json][requirements receipt]]. The paper presents prose questions and design
problems; F01–F08 are local audit identifiers. Each row distinguishes the
implemented typed contract from the broader question it addresses.

The ~LeanPoo.Functional~ namespace supplies reusable context-indexed capability
and consumer machinery. Recursive fixed points and runtime descriptors are
implemented in Prototype/Object. The latter APIs have their own evaluation and
membership proofs; selecting a Functional factory alone does not establish
those semantics for arbitrary host callbacks.

* Changed graph and cache contracts

[[file:../../contracts/graph-migrations.org][Graph migration]] now supports changed declarations, parent orders, roots and
suffix flags through the actual verified compiler. Surviving provider names
retain their complete overlays; new names receive supplied providers. Every
accepted target rechecks all watched absences and required capabilities.
Stable positive selections retain the joint proof and hot context slot;
changed selections require fresh admission. The exact preparation equality,
capability acceptance equivalence and certified availability are kernel laws.
The key/context/value family stays fixed. [[file:../../contracts/dependency-analysis.org][Analyzed computations]] infer
finite pure dependencies and required/forbidden guards, including nested helpers
and both conditional branches. Known stable footprints preserve actual cached
values/errors and context hits; affected or unknown computations require fresh
result admission. The raw capability tuple and computed output have separate
cache lifetimes. Arbitrary host closures remain outside automatic analysis.

* The local Problem API

[[file:../../../LeanPoo/Functional/Transformation.lean][Transformation.Problem]] specifies an input family, dependent results,
validity and correctness. It is a local witness-transport extension: the paper
does not define that record or supply a numbered reduction algorithm.
[[file:../../../LeanPoo/Functional/SolverTransport.lean][SolverTransport]] reuses admitted witness data; ~Certified.asSolver~ exposes
the exact Functional joint contract as such a problem. [[file:../../../LeanPoo/Functional/TransformationProfiles.lean][Profiles]] separate
decision equivalence, successful partial transport and optimality.
[[file:../../../LeanPoo/Functional/TransformationResources.lean][Resource/effect contracts]] compose declared measurements and authorized
traces. Consumers still supply implementation refinement and actual measurements.
[[file:../../../Tests/FunctionalSolverTransport.lean][Solver clients]], [[file:../../../Tests/FunctionalTransformationProfiles.lean][profile clients]] and [[file:../../../Tests/FunctionalTransformation.lean][transport clients]] check those boundaries.

* Remaining Functional work

- Finite pure computations now expose automatically inferred dependencies and
  capability guards. Arbitrary host callbacks still require explicit contracts
  and proofs; effect/termination inference remains open.
- Typed Lean dictionary/class compilation now generates exact bidirectional
  representations and transports prototype/consumer proofs. General Scheme
  source compilation and unrestricted dynamic reflection remain open.
- Runtime descriptor admission and recursive execution are implemented by their
  own modules; generic host factories have no automatic refinement bridge.
- Language-wide invalidation, general staging correctness and machine cost
  claims remain broader research work.

The Functional correspondence is now explicit. It does not change the
~whole_paper_implemented=false~ flag or turn a local witness problem into a
claim that all paper questions have been resolved.
