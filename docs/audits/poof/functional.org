* Review identity

This map uses the same pinned ~poof.scrbl~ and source intervals as the
[[file:requirements-v1.json][requirements receipt]]. The paper presents prose questions and design
problems; F01–F08 are local audit identifiers. Each row distinguishes the
implemented typed contract from the broader question it addresses.

The ~LeanPoo.Functional~ namespace supplies reusable context-indexed capability
and consumer machinery. Recursive fixed points and runtime descriptors are
implemented in Prototype/Object. The latter APIs have their own evaluation and
membership proofs; selecting a Functional factory alone does not establish
those semantics for arbitrary host callbacks.

* Small composition APIs

[[file:../../../Examples/FunctionalPipeline.lean][FunctionalPipeline]] demonstrates the reusable operations corresponding to
F01: ~Provider.compose~ for child-first capability dictionaries,
~Factory.map~ for result adaptation, ~Factory.bind~ for a follow-up at the same
context, and ~Requirements.prepareWith~ for a prepared consumer. The library
proves identity/composition, associativity, exact selected-tuple construction
and first-missing-error preservation. [[file:../../../Tests/FunctionalRequirements.lean][Generic clients]] use dependent result
families. These are Lean convenience APIs for the construction; the source does
not prescribe their names or infer requirements from arbitrary callbacks.

The same context-preserving layer includes ~Factory.choose~, ~sequence~, ~fold~
and ~recover~. Their branch, order, aggregation and exact recovery contracts
compile for dependent result families. [[file:../../../Examples/ValidationWorkflow.lean][ValidationWorkflow]] demonstrates these
APIs with bounded readings. [[file:../../../Examples/PreparedViews.lean][PreparedViews]] exercises the existing named/narrow
consumer APIs; [[file:../../../Examples/CertifiedContextCache.lean][CertifiedContextCache]] demonstrates joint admission and exact-base
dependency caching for outer requests. These are usage scenarios for the typed
construction and consumer machinery.

The more involved [[file:../../../Examples/ValidatedConfiguration.lean][ValidatedConfiguration]] applies F03's descriptor operations to
capacity-dependent nested routes and a joint total constraint. [[file:../../../LeanPoo/Functional/Codec.lean][Codec]] composes
roundtrip laws, refinements and representation changes; its existing descriptor
JSON adapters require an explicit roundtrip proof. Two wire layouts have equal
public results/errors for every input. [[file:../../../Tests/FunctionalCodec.lean][Nested controls]] use independent bounds.
[[file:../../../LeanPoo/Functional/Validation.lean][Validation]] adds all-or-error context-dependent batches and a universal
first-failure characterization, with [[file:../../../Tests/FunctionalValidation.lean][stopping and order controls]].

* Changed graph and cache contracts

[[file:../../contracts/graph-migrations.org][Graph migration]] now supports changed declarations, parent orders, roots and
suffix flags through the actual verified compiler. Surviving provider names
retain their complete overlays; new names receive supplied providers. Every
accepted target rechecks all watched absences and required capabilities.
Stable positive selections retain the joint proof and hot context slot;
changed selections require fresh admission. The exact preparation equality,
capability acceptance equivalence and certified availability are kernel laws.
The key/context/value family stays fixed. [[file:../../contracts/dependency-analysis.org][Analyzed computations]] infer
finite pure dependencies and required/forbidden guards, including nested helpers
and both conditional branches. Known stable footprints preserve actual cached
values/errors and context hits; affected or unknown computations require fresh
result admission. The raw capability tuple and computed output have separate
cache lifetimes. Arbitrary host closures remain outside automatic analysis.

[[file:../../../Examples/IncrementalWorkflow.lean][IncrementalWorkflow]] joins F04–F06 in a complete workload scenario: required
capacity, optional priority, an absent legacy method, per-job validation and a
joint result bound. Nine changes at two contexts include negative conflicts
before a missing key, add-then-remove transactions, fresh admission and a second
migration. Stable graph changes retain hot success/error observations; changing
the selected priority method can turn a cached refusal into success.
[[file:../../../LeanPoo/Functional/ComputationBatch.lean][ComputationBatch]] supplies inspectable finite sequence/traverse; the added
~Computation.validate~ retains child dependencies and reports pure check errors.
[[file:../../../Tests/FunctionalComputationBatch.lean][Batch controls]] compare independent values/errors and both cache states.
The [[file:../../contracts/validation-batches.org][scenario contracts]] record the exact function and proof boundaries.

* Checked requests and retained failure state

[[file:../../contracts/checked-requests.org][Checked request contracts]] combine the F03 concrete input/output and
parameterized descriptor constructions with the paper's pure/linear state
transformation and explicit-cache option. [[file:../../../LeanPoo/Functional/RequestHandling.lean][RequestHandling]] admits input
before its dependency read, invokes the proof-aware callback on hits too, and
returns the precise next cache even after callback/output refusal. Kernel laws
preserve every uncached outcome, the exact input-error state and read markers.
Complete input-layout adaptation preserves values/errors and returned state.

[[file:../../../LeanPoo/Functional/StatefulValidation.lean][StatefulValidation]] joins ordered admission with explicit returned state.
Its append, stateless-specialization and first-error laws retain the failing
step's exact state and skip the remaining suffix. ~ContextSlot.callBatch~
specializes those laws to the admitted request workflow.
[[file:../../../Examples/ValidatedOrders.lean][ValidatedOrders]] joins independent price/stock certificates, fresh request
labels, input/execution/output refusals and continuation. [[file:../../../Examples/ResumableRequests.lean][ResumableRequests]]
combines nested job descriptors with actual pure, mutable and linear uses of
the same batch transition. Example kernel laws specialize the existing linear
reference value semantics; actual adapters are checked by execution controls.
[[file:../../../Tests/FunctionalRequestHandling.lean][Request controls]] check 333 single calls and 15 batches in two layouts;
[[file:../../../Tests/FunctionalStatefulValidation.lean][state controls]] check 168 independent cases and 483 batch splits, with
divergent factory/suffix guards. These are convenience APIs for composing the
source constructions; the source does not prescribe a request-batch API.

* Shared consumers and different production representations

F07 separates production representations from consumer interfaces; F08 connects
class dictionaries with first-class typed values. The concrete scenarios in
[[file:../../contracts/shared-views.org][Shared snapshots and representation replacement]] join those constructions with
the explicit context-cache contract used for F02.

[[file:../../../LeanPoo/Functional/SharedViews.lean][SharedViews]] reads one broad snapshot and supplies it to several consumers,
each projecting/observing only its interface. Universal laws preserve every
dependent output and the exact broad next cache/hit pair. [[file:../../../Examples/SharedReporting.lean][SharedReporting]]
bills and monitors that snapshot, preserving repeated-key selection and hidden
broad data. [[file:../../../LeanPoo/Functional/ViewRetarget.lean][ViewRetarget]] then changes the billing production carrier using
only declared public observation equality. Its laws transfer the joint public
proof, retain hot public data and preserve every consumer output and hit decision
at every context. Candidate factories need only cover the narrow interface.
[[file:../../../Tests/FunctionalSharedViews.lean][Shared-read controls]] and [[file:../../../Tests/FunctionalViewRetarget.lean][54 retarget controls]] check context changes,
duplicates, incompatible public values and unforced private observers/functions.

[[file:../../../Examples/DictionaryConsumers.lean][DictionaryConsumers]] derives inherited tariff/quote-policy fields, composes
noncommuting prototypes, selects actual dictionaries through C3 and converts a
warm cache to fields. [[file:../../../LeanPoo/Functional/DictionaryTransport.lean][DictionaryTransport.consumeSnapshot]] decodes one
aligned snapshot for actual dictionary consumers and returns the next cache in
field representation. The example's local typeclass method call constructs a
quote carrying an inherited-law/joint-quota proof. Generic kernel laws preserve
every dependent consumer and the exact field cache state; [[file:../../../Tests/DictionaryTransport.lean][converted-method
controls]] cover hot and cold contexts alongside actual graph migrations.

These are typed applications of the concrete representation and dictionary
constructions. They do not close the source's proposed complete generalized
prototype protocol or infer equivalence of arbitrary host callbacks.

* Nested production updates and admitted dependent parts

F07 also has a concrete production constructor, ~$lens-gen~, separate from the
consumer projections above. [[file:../../../LeanPoo/Functional/FocusedUpdate.lean][FocusedUpdate]] adds total getter/setter laws,
nested composition and context-indexed factory lifting. Its ~prototype~ uses
the existing constructor; universal kernel laws preserve actual delayed
parent/child wrapping, same-part order and declared outside observations.
Independent updates commute only with explicit getter/setter independence.

[[file:../../../Examples/FocusedPricing.lean][FocusedPricing]] combines that construction with F03 input/output descriptors
and ordered stateful validation. A nested function-valued method uses cooked
self and inherited prices; its output certificate checks every supported
quantity. Exact installation transfers the certificate's bound to the actual
method. Refused updates retain the successful prefix, preserve stock/owner and
permit continuation. [[file:../../../Tests/FunctionalFocusedUpdate.lean][Controls]] compare 540 compositions and 756 batches/756
continuations against separate affine models, including unforced suffixes.

[[file:../../../Examples/FocusedAllocation.lean][FocusedAllocation]] focuses a budget-indexed allocation together with its
dependent proof. A joint descriptor admits CPU/IO values, actual delayed
construction installs a conservative transfer, and ~Factory.focus~ retains the
exact budget index and ledger metadata. Conservation and feasibility are kernel
laws; 960 movement cases use an independent target-share control.
[[file:../../contracts/focused-updates.org][The contract guide]] states the full API and evidence boundary. These explicit
typed applications do not close the proposed complete generalized protocol.

* The local Problem API

[[file:../../../LeanPoo/Functional/Transformation.lean][Transformation.Problem]] specifies an input family, dependent results,
validity and correctness. It is a local witness-transport extension: the paper
does not define that record or supply a numbered reduction algorithm.
[[file:../../../LeanPoo/Functional/SolverTransport.lean][SolverTransport]] reuses admitted witness data; ~Certified.asSolver~ exposes
the exact Functional joint contract as such a problem. [[file:../../../LeanPoo/Functional/TransformationProfiles.lean][Profiles]] separate
decision equivalence, successful partial transport and optimality.
[[file:../../../LeanPoo/Functional/TransformationResources.lean][Resource/effect contracts]] compose declared measurements and authorized
traces. Consumers still supply implementation refinement and actual measurements.
[[file:../../../Tests/FunctionalSolverTransport.lean][Solver clients]], [[file:../../../Tests/FunctionalTransformationProfiles.lean][profile clients]] and [[file:../../../Tests/FunctionalTransformation.lean][transport clients]] check those boundaries.

* Remaining Functional work

- Finite pure computations now expose automatically inferred dependencies and
  capability guards. Arbitrary host callbacks still require explicit contracts
  and proofs; effect/termination inference remains open.
- Typed Lean dictionary/class compilation now generates exact bidirectional
  representations and transports prototype/consumer proofs. General Scheme
  source compilation and unrestricted dynamic reflection remain open.
- Runtime descriptor admission and recursive execution are implemented by their
  own modules; generic host factories have no automatic refinement bridge.
- Language-wide invalidation, general staging correctness and machine cost
  claims remain broader research work.

The Functional correspondence is now explicit. It does not change the
~whole_paper_implemented=false~ flag or turn a local witness problem into a
claim that all paper questions have been resolved.
