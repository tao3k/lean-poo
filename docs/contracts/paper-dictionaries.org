* Construct an AVL dictionary

#+begin_src lean
import LeanPoo.Prototype.AVL
open LeanPoo.Prototype
unsafe def scores : Except String (Tree Int String) := do
  let order := OrderOps.instantiate
    (DelayedProto.compose OrderOps.compareMixin OrderOps.number)
  let dictionary : Dictionary Int String Unit := Dictionary.instantiate order
    (DelayedProto.compose Dictionary.avlRebalance Dictionary.binaryTree)
  dictionary.fromList [(3,"three"),(1,"one"),(2,"two")]
#+end_src

The Dictionary accumulator type parameter selects the type of ~afoldr~ results.
Use another typed dictionary family when a different fold accumulator is needed.
~afoldr~ visits left/root/right while threading an accumulator; prepending keys
therefore returns descending order. ~Tree.inorder~ returns ascending pairs.
The same insertion, lookup and fold closures serve BST and AVL variants.
Changing the node layer supplies balancing; callers need not rewrite algorithms.

* Key enumeration and dictionary merge

~KeyedPrototype~ retains a layer and its key list. Ordinary values use ~Sum.inl key~
and the key-list slot uses ~Sum.inr ()~. Instantiation publishes keys before the
layer by default; ~allowOverride := true~ lets the layer intercept this slot.
This is the paper's two prototype-representation choices, with explicit types.

~Dictionary.toList~ uses a pair-list accumulator and returns descending pairs.
~Dictionary.merge~ uses an Except/tree accumulator: override entries win over
base entries through the inherited acons method. Both operations reuse afoldr.
[[file:../../Tests/PaperRepresentations.lean][PaperRepresentations]] guards 33 merge contexts, 594 independent reads,
retained base trees, duplicate-key enumeration and both key-slot policies.

* Compose record and metadata behavior

~DictionaryRecord.compute~ receives final self; ~modify~ receives an inherited
slot and refuses a missing one. Compose with ~DelayedProto.compose child parent~.
The AVL record keeps delayed cells and inherited dictionaries shared through
Lean thunks. It does not silently turn dictionary errors into missing slots.

~MetaPrototype.make function supers precedence~ constructs a metadata object.
Use ~metadata.extend (Object.recordSlotGen .function ...)~ or the corresponding
~.supers~ / ~.precedence~ slot to derive metadata through the ordinary Object API.
~instantiate name metadata registry base~ computes a new root C3 cache and
closes the composed functions. Parent caches are observable, overridable caller
metadata; they do not carry C4 ancestry certificates. Unknown cached names,
missing slots, duplicate identities and a retained cycle back to the new root
are refused. General arbitrary cache consistency is a caller contract.

The ~fromRecord~ special base has empty supers/cache and merges constant slots
over inherited slots. This avoids an infinite tower of metadata constructors.
Typed registries replace recursive dynamic Scheme object identity. This API
implements the named meta operations; it does not provide an untyped type universe
or automatically generate every self-describing descriptor interaction.
