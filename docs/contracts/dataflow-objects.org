#+TITLE: Source-bound materialized field objects

* Problem and ownership

The legacy =Object.Memoized= local recursive =table= in =Plan.buildThunks=
is a recursive Lean function, not a heap knot. Generated native C calls the
whole table builder from the self-lookup callback. Each dependency can therefore
allocate another table. Compiling effective methods or caching reflected names
does not establish sharing of field results. The old comments claiming one
shared table have been corrected; arbitrary callbacks are not silently replaced.

=Object.Dataflow= makes finite typed field dependencies explicit through the
existing Functional =Computation= language. It is an object construction API:
C4 inheritance, typed slots, defaults, delayed super and independent family
ownership remain part of the definition. It does not introduce another evaluator.

| Stage | Owner | Retained state |
|-------+-------+----------------|
| Declaration | Dataflow Builder / StrictBuilder | Typed literals and inspectable inherited fragments |
| Source | Existing C4 graph and shared declaration merger | Exact node ownership and parent order |
| Template | GeneralizedFragments and GeneralizedGraph | Effective field programs, dependency order and rank |
| Executable preparation | ConstructionCache.Execution | Indexed resolvers and ordered dependency lists with all-key source equations |
| Instance construction | Existing ConstructionCache | Actual materialized values, completed membership, evaluated/reused work records |
| Public observation | Dataflow.Instance | Dependent indexed values, exact-source closure proof and declared inventory |
| Admission | Existing Functional.ObjectContract | Structural and domain obligations over the actual instance |

The source retains a =PreparedDeclaration= per node: its raw typed declaration,
its lowered metadata and an exact equality proof. Adding a node constructs this
owner once and shares the old owners. =Source.schema_declaration= proves that
every cached lookup, including outside the graph, is the lowering of the actual
raw declaration. =Source.add_prepared_frame= preserves every other owner.
This prevents each C4 lookup and later structural revision from rebuilding all
old slot metadata. Values and admission results remain instance-specific.

* Execution and revision

A template compiles actual C4-selected code. Replaced inherited code is pruned
before dependency analysis using =GeneralizedFragments.compile=. Dependencies
without a provider become explicit absence nodes; they never acquire a reflected
field name. Cycles and unknown opaque footprints refuse preparation.

Construction uses the existing ranked materializer. Its transient state now
uses a dependent hash table, with a kernel proof that indexed lookup has the
same meaning as each prior =setSlot= update. Completed and supported keys use
hash sets with exact list-membership equivalences. Work records prepend and
reverse once. A shared dependency is materialized once and read from that state.

The prepared Execution contains source-aligned resolver and dependency tables.
Instance construction does not reanalyze the field AST or repeatedly scan source
support for each resolver. The resulting instance table is a fixed point of the
exact compiled graph. =Instance.reference= identifies it with the ranked closure
by uniqueness; =read_reference= and =slotNames_exact= connect actual reads and
reflection to that source. These are statements about runtime-owned values,
not user-supplied labels or detached metadata.

Fresh structural revisions still add a real node and run C4 validation. For a
fresh, default-free prefix with the certified parent precedence, =resolve_prefix=
proves the exact new open-self meaning from the complete declaration frame.
=CompiledPlan.overlay= persistently updates only direct methods; duplicate direct
writes all inherit the parent table and the last direct write wins. New fields,
defaults or other topology retain the canonical preparation path.

Empty prefixes additionally use =allSlots_empty_prefix=: no second inventory
scan, method table, field-code index, dependency analysis, schedule or execution
table is allocated. The new template retains its actual new plan/source and
shares preparation only. Each instance still executes fresh materialization.

Direct replacement lowers to a constant method. =SlotSpec.withParent= specializes
non-inheriting method forms at preparation time and has an exact composition law;
the overlay drops inherited closures for constant, thunk and self methods. This
avoids resolving a parent code chain merely to discard it. Computed methods keep
their delayed inherited semantics.

The template's metadata invariant states exact plan binding and complete inventory;
=CompiledPlan.sound= certifies every retained method for every open self.
=Template.code_source= links the actual graph code to that exact plan. Requiring
storage identity with a newly allocated hash table would prevent valid persistent
sharing without strengthening these semantic guarantees.

Schedule reuse checks complete ordered support and that every new read edge was
already present. =Scheduled.restrict= proves retained ranks are valid when literal
replacement removes dependencies. New edges trigger checked scheduling; opaque
footprints still refuse preparation. Existing values and admission results are
never reused on this basis. Literal prefixes still rebuild the selected graph
code/execution indexes; their cost remains visible in the application receipts.

Under the hash-table backend assumptions, the intended materialization work is
proportional to finite support, dependency edges and actual field program work.
This is not a kernel machine-time bound. C4 preparation, dependency scheduling,
list-based reflection checks, arbitrary pure callbacks and hash collisions have
separate costs. The native cohort retains these costs in its full lifecycle.

* Type and semantic boundary

Every key fixes its value type. Computation's existential intermediate value
families put inspectable programs and their templates in Type 1. ObjectContract
Carrier and declarative predicates are universe polymorphic so admission uses
the actual object. Ordinary IO still returns Type 0; native drivers pattern-match
on pure prepared results rather than coercing or erasing typed objects.

This API admits statically inspectable finite DAGs. Conditional programs use a
conservative union of branch dependencies. It does not infer an arbitrary opaque
callback's read set, admit general recursion, guarantee dynamic branch cycles
are harmless, or equate every legacy partial callback with a finite program.
No unsafe reference cycle or new axiom supplies its fixed-point equation.

* Checks and downstream acceptance

=just check-dataflow= builds and runs 16 native controls: current-self revision,
parent preservation, missing input, cycle refusal, dead-parent pruning, topology
error order, actual once-per-field work, structural Contract admission, duplicate
slot/default refusal, disjoint families with delayed super, schedule revision,
shared dependency work, changed-edge refusal and forged-projection refusal
(the current-self control covers parent preservation together). Three further
controls cover full-preparation parity across eight revision shapes, topology
refusal and rank reuse after literal edge removal.
The source-binding, revision, specialization and construction declarations are audited against only propext, Classical.choice and Quot.sound.
The native controls and Lean example are included in the existing full gate.

=just benchmark-dataflow= runs the fixed same-cohort legacy compiled-thunk and
materialized algorithms under 120-second process limits. The saved

non-isolated diagnostic. Two later alternating pairs have no task-owned build
or test overlap. These records establish algorithm-study behavior; they do not
