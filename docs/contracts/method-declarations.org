#+TITLE: Declaration fragments and combined receiver generics

* Source correspondence

Racket's method-fragment section specifies standard qualifier order, and its
generalized-prototype section proposes a common fragment construction beyond
records. Native ~MethodDeclaration.~ advances that future work: existing ~.declare~
accepts both record metadata and method contributions, then ordinary Slot/C3
assembly supplies ~.defgeneric~ with its raw group.

* Pure laws

~Object.MethodCombination.collectFragments_append/coalesce~ preserves the exact
source stream for each selected method. ~fragmentSpecification_append~ connects
fragment blocks to delayed inherited SlotSpec assembly; ~declaredGeneric_standard~
and ~declaredGeneric_fragments~ preserve established qualifier semantics and the
original complete receiver/argument row. Typed qualifiers and a valid supplied
owner order are model premises; native grouping/linearization is tested separately.

[[file:../../Examples/DeclaredMethods.lean][Declared method examples]] prove the full two-branch standard trace, current
receiver data, around short-circuiting, failure-before-after and missing primary.
Native controls execute all five adapters, real C3 sharing, recursive declaration
roots, source edits, conflicts and the actual generic macro.

* Native limits

Only compatible local methods coalesce. Supported source edits invalidate the
registered metadata and receiver graph; raw writes and concurrent mutation remain
outside it. Generic defaults and empty inherited groups catch only their own
receiver/slot absence. Compilation does not run method bodies; invocation sequences
effects without rolling them back. Custom policies require their own laws.
No new argument-based dispatch, arbitrary-carrier fragment macro, optional-formal
grammar, compiler/runtime proof or performance claim is supplied by this bridge.

* Shared macro binding and complete current reflection

Gerbil's brace frontend now delegates its entire expression/match binding to
core ~defalias~ and the existing ~.o~ match macro. The explicit host-method
escape remains core syntax. Actual binding identity, renamed imports, nested
receiver capture and matching are host regression obligations, not Lean theorems.

~Object.CatalogReflection~ in the existing ~DescriptorReflection~ namespace
models the complete right-fold metadata inspection before name selection and
read. Its six laws retain ordered output, suffix failure, refusal before read,
selected-entry/error identity, absence refusal and whole-call congruence.
[[file:../../Examples/CatalogReflection.lean][Catalog examples]] connect current metadata to the retained method continuation
program. An unrelated metadata failure must still prevent a front-slot read;
early-exit reflection would change this observation. Effective declarations and
stable supplied callbacks are explicit premises. Source invalidation, real macro
expansion and retry execute in the Scheme FUN example and regression suite.
This integration advances the article's future MOP work; it is not a runtime or
compiler proof, and does not close the other TODO workstreams.

* Ordered declaration traversal and complete finalization

The Gerbil driver now uses standard ~map-in-order~ followed by ~foldr append []~
inside the existing FUN Observation. Per-form proper-list checks precede the
suffix; finalization receives the whole batch and current context. Preparation
captures each form binding. Mutable chunk copying remains deferred until all
callbacks complete, and source revisions retain their original rejection guards.
The integrated Scheme example constructs tenant/private metadata and a complete
qualifier group above the shared C3 family, then reflects and invokes it.

~DeclarativeMetadata.collectForms~ delegates to Lean ~List.mapM~ and flattening.

The monadic law assumes ~LawfulMonad~. ~Examples/MetaBootstrap.lean~ checks
