#+TITLE: Controlled non-record closure and custom lens laws

* Bounded raw stabilization

~Generalized.closeWithin~ reuses the existing fragment protocol and actual raw
equality. Every success has a ~Generalized.Closed~ equation, a transition count
within budget, provenance from the ORIGINAL seed and stable later unfoldings.
The final adjacent equality verification counts as one transition. Exhaustion
is inconclusive about divergence; the budget does not bound arbitrary callback
time, law-domain checking or allocation.

Native ~generalized-closure.ss~ follows the same first-order comparable-carrier
construction under purity/immutability premises. It never accepts sampled
procedure outputs as raw equality. Its owner/base-bound receipts publish only
after successful cooking; budget, law and source refusal retain the old version.
Opaque native callback exceptions and runtime equality implementation are native
controls, not a universal compiler/runtime proof.

* Universal laws and finite controls

~Prototype.LensLaws~ states get-put, put-get and put-put for arbitrary custom
getter/setter functions, proves composition and retains the existing MonoLens
view/no-op semantics. Native ~lens-laws.ss~ checks the corresponding equations
on supplied states/values, holding registered dependencies stable through the
whole closure. A finite passed check is not a universal law certificate.
Impure mutation and unregistered/concurrent sources remain outside the protocol.

* Paired example

[[file:../../Examples/ClosedPrototypes.lean][Closed prototype examples]] prove nested custom lens laws, a lossy-lens
counterexample and actual closure of a three-component product dependency chain

This advances generalized-prototype future work. No performance result or new

* Focused component closure and final family admission

~Generalized.closeFocused~ reuses bounded closure from the actual viewed seed,
then replaces that component in a wider raw carrier. Given ~LensLaws~, success
exposes the same local fixed point. Independent audit/frame preservation needs
an explicit setter frame law; it is not implied by the three lens laws alone.
~closeFocused_reached~ proves the replacement comes from the actual viewed seed's
finite unfolding before budget exhaustion.
~LensIndependent~ states cross-view preservation and commuting writes, and
~LensLaws.pair~ proves lawful product assembly under these additional premises.

Native ~focused-closure.ss~ assembles ordered stages using standard ~foldr~ and
the existing FUN Reader ~.map~. All registered sources stay guarded across ALL
stages, final raw-equation validation and whole-family cooking. Actual old/new
child values extend finite outer-lens checks. Final validation checks EVERY
local raw equation again, since individually lawful lenses can overlap.
Each final validation performs one extra raw transition beyond its search budget.
~validateFocused_sound~ proves the corresponding pure admission equation.

The paired example closes two services inside a shared audited product/vector,
retaining existing child method combinations. It proves outer custom lens laws,
their independence, frame preservation and actual two-service results. Conflicting
updates through the same lawful lens fail final admission and retain the old
publication; compatible overlap may pass. A heterogeneous service/scalar example
uses different raw/cooked/focus types under the same final admission. No arbitrary dependency scheduler,
mutual-recursion solver, unrestricted procedure equality or effect rollback follows.
The construction advances the generalized-prototype future work.

* Controlled cyclic component equations

~FeedbackClosure~ reuses the same generalized lens compiler and bounded wider-raw
search. Every accepted feedback preparation satisfies BOTH the assembled fixed
equation and each COMPLETE component equation against the same cooked global self
and original base. This excludes cancelling overlapping method contributions;
ordinary incremental inheritance remains a separate existing interpretation.

~closeWithin_complete~ proves success within d+1 raw calls when actual convergence
at depth d is supplied. ~closeFeedback_complete~ additionally requires component
residual validity. Soundness, seed provenance, later stability and frame/budget
laws reuse existing fixed-point proofs. No automatic convergence or leastness is
inferred for arbitrary equations.

[[file:../../Examples/FeedbackServices.lean][Feedback service examples]] prove a capped three-service ring plus joint
approval closes within five calls from ANY typed seed at cap=3, with universal
custom lens laws and preserved audit. Existing primary/around methods consume
the final approved state. Native ~feedback-closure.ss~ / ~examples/feedback-services.ss~
reuse FUN Reader, complete-source declaration finalization and finite lens checks.
All sources stay guarded through search/cooking/residual admission. Search counts
whole-raw calls; residual checking adds one component compiler call per descriptor.
Staged cooking precedes residual admission and reuses its cooked self; failed
admission retains old publication but cannot roll back arbitrary external effects.
This is generalized-prototype future work, not a Scheme runtime verification or
performance claim. Unrestricted recursive knots and function equality remain open.

* Shared dependency and cross-service revision

~FeedbackRevision~ treats previous raw only as a new search seed, then requires
current joint approval on the exact revised closed raw. It proves fresh component
equations, previous-seed provenance, approval and raw transition bounds by reusing
the controlled feedback model. No prior proof or approval is copied across sources.

[[file:../../Examples/SharedFeedback.lean][Shared feedback examples]] align one quota node, two nested service branches in
a four-node feedback ring, joint readiness, existing primary/around methods and
current cross-service budget/permission checks. Cold, growing, decreasing,
overcommitted, unchanged-but-denied and insufficient-budget examples use the actual
closure search. ~admitted_joint~ proves permission, readiness, coherent quota and
joint commitment for ANY accepted example revision. Custom nested lens laws use
the reusable product laws/composition; explicit frame laws preserve the audit.

Native ~feedback-revision.ss~ retains all preparation/check source guards through
the current approval callback, using FUN Reader ~.map~. Any refusal retains the
exact old publication; example source preparation is inside that boundary too.
Runtime source writes, malformed/non-Boolean metadata and callback failures have
native controls. Pure raw-predicate proofs do not verify arbitrary receipt-aware
native callbacks or the runtime/compiler. Source registration, purity/immutability
and typed domains remain premises. No selective cyclic reuse or speedup follows.
This advances the generalized-prototype future work; functionality precedes tuning.
