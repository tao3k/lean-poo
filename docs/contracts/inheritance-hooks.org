#+TITLE: Inherited hooks and declared source revisions

* Functional scope

This advances the paper's future generalized MOP. Native inherited protocols
intercept existing C3 and effective-slot construction. Order hooks may wrap or
refuse, but acceptance preserves canonical C3; custom slot transformations need
their own laws. ~InheritedMOP.checkedOrder_sound~ proves accepted order identity,
~checkedOrder_error~ source-error precedence and ~composeHooks_assoc~ compositional
wrapper grouping. Callback effects are not identified with pure functions.

* Source ownership

~Object.invalidateCaches~ reuses ~Proof.invalidatedNodes~, including its finite
reverse-reachability theorems. ~invalidateCaches_descendant~ clears every bounded
registered descendant, ~invalidateCaches_once~ increments one revision per owner,
and ~invalidateCaches_frame~ retains unaffected owners. Native source edges include
parents, protocol objects, declaration descriptors and their types. Weak reverse
keys and visited owners implement the native traversal; the kernel model is not
a proof of the native hash-table runtime or GC. Missing external dependencies
must be registered explicitly. Supported writes are sequential, preflight active
owners and support optional sealing; raw struct setters are trusted escape hatches.

* Declaration admission

~Prototype.DescriptorReflection~ reuses ~Descriptor.validate~ for public slot
writes and checks visibility before selecting a read/write callback. ~readSlot_valid~ ensures cached/default/hook results meet current descriptors,
without caching approval. Invalid writes do not select mutation. Native Slot metadata compiles through its existing
~.slot.define~ / ~.slot.check~ methods and is recompiled after descriptor/type edits.
The Class bridge captures the effective-slot catalog at construction; whole-class
constraints still require explicit admission after edits. No global access-control
or automatic dependency-discovery claim is inferred.
