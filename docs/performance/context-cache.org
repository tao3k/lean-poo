* Workload and matched controls

The [[file:../../Benchmarks/receipts/context-slot-native-2026-10-05.json][v1 native receipt]] records 96 samples:
two key counts (8/32), two factory work counts (0/1024 UInt64 recurrence steps),
three request schedules, four alternating pairs and two variants. Every query
has 256 requests. Hit repeats context 7; miss alternates 0/1; blocks repeats
each context eight times. Both controls prepare the same certified functions
and materialize the same warm snapshot at context 7 in an IO cell. Setup and
query are measured separately. State-cell creation and process startup are
outside query timing. Query includes result construction, checksum accumulation,
IO state access and dependency builds or cache matching/replacement.

A separate scalar recurrence and key loop, after timing, checks every output
checksum. A schedule oracle checks cache decisions. Uncached performs no reuse;
cached reports 256/0/224 reused reads for hit/miss/blocks. Payload and the
uncached consumer are noinline. Both produce the same visible results.

* Structural identity path and non-winning controls

The existing native =contextSlotScale= executable also accepts
=structural MODE SIZE READS=, where MODE is =same=, =equal= or =miss=.
Use =lake build contextSlotScale= followed by, for example,
=.lake/build/bin/contextSlotScale structural same 8192 256=.
Lean owns construction, one warmup, three fixed samples, scalar checksum and
reuse-policy guards, and emits official =measurement:= lines. Each sample includes
warm snapshot construction and 256 reads; process startup is outside these clocks.
The original scalar CLI and workloads are unchanged.

The same workload was compiled before and after the standard checked identity
shortcut. A noinline list copier creates the equal-context control outside the
timed reads. The changed-context control alternates replacement. No workload is
rerun to discard a slower observation.

| Mode | Baseline milliseconds | Candidate milliseconds |
|------+-----------------------+------------------------|
| Same retained owner | 26.858416 / 26.921000 / 27.329709 | 0.027583 / 0.025667 / 0.027083 |
| Independent equal context | 27.996583 / 28.702084 / 29.788084 | 51.590167 / 156.058542 / 56.726500 |
| Changed context, all misses | 32.622250 / 29.795459 / 30.206583 | 29.432375 / 75.595125 / 301.812084 |

Generated C places the identity comparison before allocating the structural
comparison closure. The fallback contains one original structural decision,
not two; slower equal/miss observations remain non-winning evidence. They are
not assigned an exclusive host/scheduler cause. This qualifies the retained-owner
case, not universal acceleration, a whole application, OS startup or peak memory.
All data, slot, reuse flags and dependent Claims retain the original semantics;
=ContextSlot.read_reference= uses only standard =propext= and all previous laws
remain. Application/native pipeline evidence is recorded by its actual consumer.


* Adopted owners and lawful short-circuit equality

The next revision changes the existing slot, rather than adding a cache. An
independent equal hit adopts the requested context index while keeping certified
built data. The full reference theorem still compares the old snapshot/slot/hit
tuple, for an arbitrary reference DecidableEq. All fourteen shared context modules
pass computational =BEq= plus =LawfulBEq=; projections, requests, dictionary
transport and Contract adapters no longer silently select decision-code fallback.
Both read and consume are inline so a projected caller can remove result tuples.

Static inspection of the original native =List= DecidableEq image identifies a
costly negative path: it calls =List.hasDecEq= on the tail before the head decision.
Thus the changed-head 8192-element workload still walks long tails on misses.
The new compiled lawful List BEq checks the head before advancing. It establishes
exact equality by LawfulBEq, not by an unchecked Boolean or a fingerprint.

Keep every first candidate and final-candidate observation. All workloads retain
one warmup and three samples; SIZE=8192 and READS=256. The original scalar CLI
and original structural workload/checksum/hit expectations are unchanged.
